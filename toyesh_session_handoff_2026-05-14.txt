   AgingEntry schema:

     amount: float              # total gross open amount (EUR, incl. VAT)
     aging_bucket: str          # "0-30" | "31-60" | "61-90" | "90+" | "—"
     invoice_ref: str | null    # first invoice reference for this counterparty

   Top 10 counterparties by amount; rest rolled into "Other (N entries)" bucket.
   These are OPTIONAL fields (default []). Existing frontend code won't break.
   Accessed at: analysis_result.readiness.ratios.ar_aging_detail

   HOST SPECIFICALLY ASKED FOR THIS — should be visible in the demo.
   Suggested UI: expandable table under DSO/DPO tiles on the Report page.
   See deferred.txt on the toyesh branch for full UI spec.

3. AGENTIC FIX-PLANNER (backend_FastAPI_emma/services/fix_planner.py + analyze.py)
   Two new endpoints:

   POST /api/v1/fix-plan
   Query params: period_start (date, optional), period_end (date, optional)
   Returns: FixPlan

   PUT /api/v1/fix-plan/{plan_id}/approve
   Body: { "approved_items": ["check_id1", ...], "notes": "..." }
   Returns: { "logged": true, "plan_id": "...", "approved_items": [...] }

   FixPlan schema:
     plan_id: str              # UUID
     generated_at: str         # ISO datetime
     period_start: str         # "2024-01-01"
     period_end: str           # "2024-12-31"
     items: FixPlanItem[]
     ai_disclosure: str        # pre-filled EU AI Act transparency text

   FixPlanItem schema:
     check_id: str
     issue_summary: str        # one sentence plain English
     proposed_action: str      # specific Exact Online step with account codes
     affected_accounts: str[]  # e.g. ["1250", "4xxx"]
     estimated_effort: str     # "< 5 minutes" | "30 minutes" | "1-2 hours" | "Half day" | "Requires accountant review"
     confidence: "high"|"medium"|"low"
     risk_level: "low"|"medium"|"high"
     supporting_data: str[]    # amounts/IDs from the actual report data

   This is the plan-mode feature the host asked about. Claude proposes concrete
   Exact Online actions, advisor reviews each item, approves/rejects. Human always
   executes — AI never writes to Exact Online.

   Suggested UI: "Generate Fix Plan" button on Advisory page (visible when advice_ready=False).
   Show review cards with approve/reject/note per item + "Approve selected" button.
   Include the ai_disclosure text as a banner at top (EU AI Act Art. 13 compliance).
   See deferred.txt on toyesh branch for full UI spec.

4. CBS SECTOR BENCHMARKS (backend/services/benchmarks.py)
   Every AnalysisResult now includes sector_benchmarks at the top level.

   SectorBenchmarks schema:
     sector_name: str                # "Reparatie van overige consumentengoederen (SBI 95.29)"
     sbi_code: str                   # "95.29"
     source: str                     # "CBS StatLine SBS 2022 / ING Sector Monitor 2023..."
     reference_year: int             # 2022
     gross_margin_median: float|null # 0.42 = 42%
     revenue_per_fte_median: float|null  # 88000.0 (EUR)
     dso_days_approx: float|null     # 18.0
     dpo_days_approx: float|null     # 35.0
     notes: str                      # always show this note with the data

   Accessed at: analysis_result.sector_benchmarks
   Optional field — null if CBS API times out (10s timeout, non-fatal).

   Suggested UI: "Sector context" panel on Report page showing company metric
   vs sector median side-by-side. Always show the source string (citable data).
   See deferred.txt on toyesh branch for full UI spec.
