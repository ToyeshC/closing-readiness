=== 4. backend_FastAPI_emma/ — Emma's full API layer ===

New folder: backend_FastAPI_emma/

This is intentionally separate from your backend/ folder so both workstreams can
develop in parallel without touching each other's files.

Structure:
    backend_FastAPI_emma/
    ├── __init__.py
    ├── main.py              FastAPI app, CORS, mounts router at /api/v1
    ├── schemas.py           AdvisoryOutput + AnalysisResult (Emma-owned output models)
    ├── routers/
    │   └── analyze.py       The two API endpoints
    └── services/
        └── reasoning.py     Anthropic API integration

--- schemas.py ---
Defines two Pydantic models that Emma owns (kept out of models.py):
- AdvisoryOutput: type (FACT/ASSUMPTION/ADVICE), statement, source,
  source_record_ids, confidence
- AnalysisResult: wraps DataReadinessReport + advisory_outputs (or None) +
  blocked_reason

These are Emma's output contract, equivalent to your FinancialDataset/DataReadinessReport.

--- main.py ---
Boots the FastAPI app. CORS is configured to allow localhost:3000 (Next.js dev)
and the production Vercel URL (set via FRONTEND_URL env var). Router is mounted
at /api/v1. Includes a GET /health endpoint.

Start with:
    uvicorn backend_FastAPI_emma.main:app --reload

--- routers/analyze.py ---

POST /api/v1/readiness
    Query params: period_start, period_end (default: 2024-01-01 / 2024-12-31)
    Calls: backend.services.data_loader.load_all()
    Then:  ReadinessEngine(dataset).run()            ← THIS IS YOUR CODE
    Gate:  if not report.advice_ready → return blocked result (no Claude call)
    Else:  call_claude(report) → list[AdvisoryOutput]
    Returns: AnalysisResult

GET /api/v1/readiness/{check_id}/sources
    Returns: list[SourceLine] for the given check_id
    Source: looks up the last cached DataReadinessReport (module-level variable)
    Used by: the "Show source" button in the frontend

DATA_FOLDER defaults to "00 Dataroom hackathon" (relative to repo root).
Override with DATA_FOLDER env var if needed.

CRITICAL DEPENDENCY: analyze.py imports ReadinessEngine from
backend.services.readiness_engine. This import will fail until you push your
engine. Everything else runs fine now. Once you merge your engine to main and
Emma pulls, the full POST /api/v1/readiness route will be live end-to-end.

--- services/reasoning.py ---
The Claude integration. Only called when report.advice_ready == True (the route
enforces this; reasoning.py trusts it).

Key design decisions:
- Uses _build_context() to send a SUMMARISED view of the data, not raw dumps.
  Sends: sales/purchase/bank summaries (count + total + 3 sample rows), up to 20
  asset register rows, list of warnings and passed checks.
- System prompt enforces FACT/ASSUMPTION/ADVICE typing and forbids numbers not
  present in the provided data.
- max_tokens=1000 (raise to 2000 if outputs are cut off).
- If Claude's JSON can't be parsed, returns [] rather than surfacing garbage.
- Model: claude-sonnet-4-20250514

The _summarise() function reads the "bedrag" column for amounts (Dutch column
name from your data loader). If the field is missing it falls back to 0 safely.
