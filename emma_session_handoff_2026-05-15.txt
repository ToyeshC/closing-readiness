CRITICAL — BEFORE THE DEMO
---------------------------
1. RESTART UVICORN — the load_dotenv fix only takes effect on restart. If the backend
   is still running from before this session, ANTHROPIC_API_KEY won't load correctly
   and Claude calls (fix plan, insights) will fail with auth errors.

   Kill and restart:
     uvicorn backend_FastAPI_emma.main:app --host 127.0.0.1 --port 8000 --reload --workers 1

   !! --workers 1 is REQUIRED — the /readiness/{check_id}/sources endpoint reads a
   module-level cache (_last_report) that is only populated by the POST /readiness handler.
   Multiple workers won't share this cache.

2. PULL MAIN before running anything:
     git checkout main && git pull origin main && git checkout toyesh

3. Run the readiness check FIRST before clicking "Generate Insights" or "Generate
   Remediation Plan" — both endpoints depend on the _last_report cache which is only
   set by POST /api/v1/readiness.

4. For OAuth: ngrok must use 127.0.0.1 (not localhost) to avoid macOS IPv6 resolution:
     ngrok http --domain=unwired-sweep-apostle.ngrok-free.dev 127.0.0.1:8000


API CONTRACTS — WHAT CHANGED TODAY
------------------------------------
New endpoint:
  POST /api/v1/insights
  → Response: InsightsResult {
      whats_working: string | null,
      early_warnings: [{check_id, check_label, signal, recommendation}],
      check_correlations: [{check_ids: string[], explanation}],
      client_letter_nl: string | null
    }
  → Requires: POST /api/v1/readiness must have been called first (uses _last_report cache)
  → Returns 409 if no cached report

AnalysisResult now includes:
  trace_id: string | null   (8-char uppercase UUID, shown in report hero)
