=== 1. THE SHARED CONTRACT: models.py ===

Create backend/models.py with exactly this content:

    from pydantic import BaseModel
    from typing import Literal
    from datetime import date

    class SourceLine(BaseModel):
        entity: str          # "gl_entry", "invoice", "bank_statement"
        record_id: str
        account_code: str
        amount: float
        date: date
        description: str
        raw: dict            # full original record — never discard this

    class ReadinessCheck(BaseModel):
        check_id: str
        label: str
        status: Literal["pass", "warn", "fail", "blocker"]
        severity: Literal["low", "medium", "high", "blocker"]
        description: str
        affected_amount: float | None
        source_lines: list[SourceLine]

    class FinancialDataset(BaseModel):
        period_start: date
        period_end: date
        gl_entries: list[dict]
        opening_balances: list[dict]
        sales_entries: list[dict]
        purchase_entries: list[dict]
        bank_entries: list[dict]
        relations: list[dict]
        asset_register: list[dict]
        intercompany: list[dict]
        tax_schedule: list[dict]
        items: list[dict]
        item_groups: list[dict]
        todo_discrepancies: list[dict]  # files in to do/ vs main — already populated by data_loader

    class DataReadinessReport(BaseModel):
        dataset: FinancialDataset
        overall_score: float       # 0.0 to 1.0
        advice_ready: bool         # True only if zero blockers
        checks: list[ReadinessCheck]

=== 5. DEMO SEQUENCE — what the UI must support ===

This is what the judges are looking for. Build in this order:

1. "Run readiness check" button → calls POST /api/v1/readiness
2. Results screen shows:
   - Overall score (0.0–1.0) as a percentage or progress bar
   - List of checks with status icons (pass = green, warn = yellow, fail = red, blocker = red)
   - Each failing check shows: label, description, affected_amount in euros
3. "Show source" button on each failing check:
   → calls GET /api/v1/readiness/{check_id}/sources
   → shows a table of the exact GL rows/transactions that triggered the issue
4. If advice_ready = False:
   → Show a blocked advisory screen
   → Message format: "[check description]. AI advice is disabled until this is resolved."
   → Do NOT call Claude
5. If advice_ready = True:
   → Call Claude with the financial data and display advice

The "Show source" → raw Dutch GL rows moment is the key judging criterion.
The system refusing to hallucinate on dirty data = the responsible AI story.

=== 7. DUTCH DATA — COLUMN NAMES FOR REFERENCE ===

If you ever need to debug raw data coming back from the engine:

GL journal entries (03_general_journal_entries...):
    Boekdatum           = booking date
    Bedrag              = amount (signed float, positive = debit, negative = credit)
    Grootboekrekening   = GL account code (e.g. 8000 = revenue, 4000 = payroll costs)
    Omschrijving        = description
    Boekstuknummer      = document/batch ID (e.g. J240001)
    Periode             = fiscal period (integer 1–12)

Bank entries (05_bank_cash_entries...):
    Datum               = transaction date
    Bedrag              = amount (signed)
    Naam                = counterparty name
    Code                = counterparty relation code
    Omschrijving        = description

Sales/purchase entries (04 and 05):
    No header row — positional format loaded with header=None
    Position 3  = invoice number
    Position 5  = invoice date
    Position 13 = relation code (debtor or creditor ID)
    Position 15 = GL account code
    Position 19 = amount excl. VAT
    Position 21 = VAT amount (BTW-bedrag)

Key account code ranges:
    0xxx = fixed assets (CAPEX)
    1250 = suspense/clearing (unidentified transactions — "Nog te duiden")
    13xx = accounts receivable
    17xx = accounts payable
    1870 = VAT accounts
    4xxx = operating expenses (OPEX, personnel)
    7xxx = cost of goods/services
    8xxx = revenue

Data files location: 00 Dataroom hackathon/ — NOT in git (financial client data).
